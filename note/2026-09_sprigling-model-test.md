## 本文

ご無沙汰しています。ゲーム開発のほうが楽しくなりすぎて、しばらくnoteを放置していました。

今日はまず数字の報告から。

2か月以上かけて作ってきた対戦ゲーム『Stonebloom』のプロトタイプをitch.ioで公開してみました。結果はこうなりました。

| 指標 | 数値 |
|---|---|
| ページビュー | 77 |
| ブラウザでのプレイ | 6 |
| 評価 | 0 |
| コレクション | 0 |
| コメント | 0 |
| 7日間のインプレッション | 38 |

評価もコメントもゼロでした。遊ばれた回数は6回で、そのうち何回が自分によるものかは考えないことにしています。

この記事では、この結果を受けて何を考え、何を変え、いま何に興奮しているのかを書きます。

### Stonebloomはどんなゲームだったか

Stonebloomは、囲碁の「囲んでダメージを与える」感覚と、将棋の「駒ごとに役割が違う」面白さを組み合わせた、1局10分程度の対戦ゲームです。9×9の盤で5種類の駒を動かし、相手の本拠を壊すか、勝利点で上回れば勝ちです。

裏側ではPythonで数万局の自己対戦を回し、AIを戦わせながら「どの駒が強すぎるか」「先手が有利すぎないか」を数字で詰めてきました。ルールの手触りには今でも自信があります。

### なぜ誰にも遊ばれなかったのか

振り返ると、理由ははっきりしていました。

- **サムネイルを見ても、何が面白いのか伝わらない。** 盤と駒が並んでいるだけの画面は、遊べば分かる面白さがあっても、一覧の中で指を止めてもらえません。
- **「囲碁×将棋」と聞いた時点で身構えてしまう。** ルールを覚える前に、読む気力を奪ってしまっていました。
- **「このキャラが好き」と思える存在がいない。** 対戦ゲームを遊び続ける動機として、愛着はルールと同じくらい大事だと痛感しました。

ゲームの中身ではなく、入口で負けていたのだと思います。

### 眠っていた企画「Whittlewisp」を組み込む

そこで思い出したのが、以前ひとりで温めていた企画『Whittlewisp（ウィットルウィスプ）』です。

Whittlewispの核は「**見た目がそのまま性能になる生き物**」です。

- 首が長ければ、高いところまで届く
- 脚が長ければ、速く動ける
- 腕が大きければ、力が強い
- 尻尾が大きければ、倒れにくい

ステータス画面を見なくても、相手の体つきを見れば戦い方が分かる、というゲームです。この生き物を「Sprigling（スプリグリング）」と呼んでいます。魔法で作られた人形で、Whittlewispという町に住む小さな妖精が乗り込んで操ります。

これをStonebloomの盤の上に乗せたらどうなるか、と考えました。

Stonebloomには「盤上の駒の戦い」という土台と、それを検証してきた仕組みがあります。Whittlewispには「自分だけの生き物を作る」という愛着の入口があります。二つを合わせると、**自分で作った生き物を、仲間の駒と一緒に盤上で戦わせるローグライト**になります。ダンジョンを進みながら体のパーツを集め、ボスに挑む遊び方です。

試しに設計をまとめてみると、手応えがありました。Stonebloomの弱点だった入口と、Whittlewispの弱点だった「戦闘の奥深さを何で支えるか」が、お互いをちょうど補い合っていたからです。

### モデルテスト：40体、全部別物

いまUnityでSpriglingのモデルを組み立てるテストをしています。それが冒頭の画像です。

（ここにモデルテストのスクリーンショット）

これは、体の部位の数・大きさ・長さ・取り付け方をランダムに決めて並べたものです。頭・首・胴体・腕・脚・翼・尻尾・目・耳・鼻・口の11部位を組み合わせています。

作った本人が言うのもなんですが、並べた瞬間、声が出ました。

- 首がやたら長くて、頭だけ空に突き出している子
- 翼が大きすぎて、飛べそうにない子
- 頭が3つあって、それぞれに目と口がついている子
- 脚が4本の、しっかりした四つ足の子

**一体も同じ子がいません。** しかも「見た目＝性能」なので、この見た目の違いはすべて戦い方の違いになります。首の長い子は高いところを狙えますし、脚が4本の子は倒れにくくなります。

どの子が強いのかは、まだ私にも分かりません。

### 数えきれないキャラのバランスは、取れるのか

ここからが本題です。

部位の組み合わせは事実上無限です。そして「見た目＝性能」を掲げる以上、「このキャラだけ強すぎる」が起きたとき、見た目をいじって直すことはできません。

ここで役に立つのが、Stonebloomで2か月かけて作ってきた検証の仕組みです。

- 駒ごとに「動員コスト」があり、強い駒ほど高くつく
- AI同士で数千局を自動で戦わせ、勝率の偏りを数字で見る

Spriglingも、体の重さに応じて動員コストが決まる駒として盤に乗せます。そしてAI同士に戦わせ、「コストの割に強すぎる体」がないかを探しています。

実際に回してみると、想像していなかったことがいくつも分かりました。

- **正面からの攻撃は全体の11%しかなかった。** 横からが40%で、多くの戦いは横腹の削り合いになっていました。
- **翼が優秀な盾になっていた。** 攻撃を受けた部位の20%が翼でした。背中を守るつもりで付けた翼が、横や正面からの攻撃まで受け止めていました。
- **相手より多く撃破した側が75%の確率で勝つ。** 盤上で殴り合った結果が、ちゃんと勝敗に反映されていることが確認できました。

いちばん悩んだのは、ある時点で検証側が出してきた「バランス修正」でした。一つの部位を極端に大きくするビルドが強すぎたので、体全体の性能を配分し直すという修正です。数字の上ではうまくいっていました。

でもこれは、**ある部位を大きくすると、見た目の変わらない別の部位が弱くなる**ということです。「見た目＝性能」の約束を破ってしまいます。

なのでこの修正は差し戻し、「見た目＝性能は絶対」をルールとして明文化しました。強すぎる問題は、性能ではなくコスト側（大きな部位ほど割高になる、など）で直す方針です。

数字で詰めていく検証と、「このゲームは何を約束するのか」という軸を、行ったり来たりしながら進めています。

### これからやること

- 盤上で生き物がどう傾き、どう倒れるかを目で確認できるようにする
- 正面から戦う理由を増やす（盤の広さや本拠の位置を見直す）
- ダンジョンを進んでパーツを集める、ローグライト部分のプロトタイプ

### おわりに

itch.ioの77ビューは、正直落ち込みました。でもあの結果がなければWhittlewispを引っぱり出すこともなく、この40体にも出会えませんでした。

今後はこのマガジンで、Spriglingが増えていく様子や、バランス検証で見つけた「予想外の強い体」を定期的に紹介していきます。
